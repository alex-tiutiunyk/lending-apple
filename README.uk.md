## Технології

| Напрям             | Інструменти                                                                                                           |
| ------------------ | --------------------------------------------------------------------------------------------------------------------- |
| **UI**             | React 19 (`hydrateRoot`, `lazy` / `Suspense`, `useSyncExternalStore`), TypeScript 5.8 у strict-режимі                 |
| **Збірка**         | Vite 6: клієнтська збірка, SSR-збірка та пререндер у статичний HTML                                                   |
| **Стилі**          | SCSS-модулі з читабельними BEM-класами, дизайн-токени, container queries у rem                                        |
| **Анімація**       | CSS scroll-driven анімації, keyframes лише на компоновнику, Canvas 2D, SVG, один власний цикл `requestAnimationFrame` |
| **Тести**          | Vitest + Testing Library + jsdom; Playwright у Chrome, Pixel 7, Firefox, iPad та iPhone (WebKit); axe-core            |
| **Якість коду**    | ESLint 9 (typescript-eslint strict, jsx-a11y, react-hooks), Stylelint, Prettier, knip, madge                          |
| **Продуктивність** | Власний пробник через Chrome DevTools Protocol: час кадру, довгі задачі, перерахунки стилів, шари                     |

Єдині runtime-залежності — `react` і `react-dom`. Жодних GSAP, Framer Motion, Lenis чи Lottie.

## Що вирішено

### Анімація

- **Один цикл кадрів на всю сторінку.** `src/hooks/frameLoop.ts` володіє єдиним `requestAnimationFrame`, єдиним слухачем скролу та єдиним слухачем вказівника. Кожен кадр спершу виконує фазу читання, а потім фазу запису, тож сторінка ніколи не змушує браузер перераховувати розкладку, змішуючи їх. Цикл зупиняється, щойно ніщо не рухається.
- **Скрол — це таймлайн, а не змінна в JS.** Закріплені секції, розібраний телефон, появи тексту та лінія прогресу працюють на `animation-timeline: scroll()` / `view()`, тож їх анімує компоновник. У Firefox немає scroll-таймлайнів, тому там ті самі keyframes створюються на паузі, а їхній `currentTime` іде за скролом. React не перерендерює нічого під час скролу.
- **Середній час кадру за повний скрол упав із 68 мс до 17,8 мс.** Найбільше дали дві речі: жодної custom property, що пишеться щокадру на `<html>` чи секцію (один успадкований запис перераховував стилі 1 870 вузлів), і нескінченні анімації лише на `transform` / `opacity`. Тести в `config/` падають на будь-який `will-change` поза дозволеним міксином і на будь-яку щокадрову custom property, що успадковується.
- **Розібраний телефон із плоских SVG-шарів**, якому глибину дає лише `translateZ`. Він збирається в готовий телефон із екраном блокування, відблиском і справжньою товщиною рамки, і все це від одного значення прогресу.
- **Частинки, що складаються у фігури.** Поле на Canvas 2D біля кожного зображення збирає свою фігуру. Коли дві цілі поруч, частинки діляться між ними, а не розпливаються в одну пляму. 400 точок логотипа обчислюються під час збірки.
- **Літери, що тікають, не чіпаючи DOM.** CSS Custom Highlight API робить гліф прозорим, поки його копія на ніжках тікає в оверлеї. Текст, кернінг і виділення лишаються цілими.
- **Маскот із фізикою.** Pip ходить низом вікна, оминає посилання й поля форми, його можна перетягнути й кинути. Він приземляється на одному з семи пристосувань (парашут, повітряні кульки, планер…). Міні-Піпи грають у футбол на рендері телефона.
- **Те, що поза екраном, спить.** `content-visibility: auto`, перемикач `[data-awake]` для фонових циклів і ліниві чанки, що вантажаться, коли сторінка вже інтерактивна, і зовсім не вантажаться, якщо рух зменшено.

### Не лише анімація

- **Перше відмальовування без JavaScript.** Сторінка пререндериться під час збірки. Inline-скрипт у `<head>` застосовує збережений колір корпусу та налаштування доступності до першого відмальовування, тож перезавантаження ніколи не блимає типовими значеннями.
- **Справжня панель доступності.** Рух: Повний / Спокійний / Вимкнений. Розмір тексту від 100 до 200 % (розкладка підлаштовується через container queries у rem). Висока контрастність 7 : 1. Світла тема. Інтервали для читання за WCAG. Контраст для кожної комбінації обчислюється в юніт-тесті й ще раз перевіряється axe.
- **Читабельні імена класів CSS-модулів.** Власний `generateScopedName` перетворює хеші на BEM (`exploded-view__stack`), а тест це гарантує.

## Запуск

```sh
npm install
npm run dev        # http://localhost:5173
npm run build      # перевірка типів, збірка, пререндер
npm test           # Vitest
npm run test:e2e   # Playwright у 5 профілях браузерів
```

Як працює кожен ефект, правила продуктивності, таблиця бюджетів і відомі прогалини описані в [`docs/README.md`](docs/README.md) (англійською). Плани, за якими будувалася сторінка, лежать у [`docs/`](docs/).
